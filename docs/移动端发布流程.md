# 安卓发布流程（M5）

对应 `docs/移动端适配计划.md` §3 M5「签名 keystore + 脚本化 + 分发文档」。
桌面发版见 `CONTRIBUTING.md`「发布新版本」，两者是**两条独立链路**，钥匙也不是同一把。

---

## 0. 一页纸流程

```powershell
# 真机测试用的调试包（不需要任何密钥；cmd 下把 `$env:X = ...` 换成 `set X=...`）
pnpm android

# 正式包：四个架构齐出 + zipalign + apksigner 签名 + 验签
$env:MINDSCAPE_APK_KEYSTORE  = "$env:USERPROFILE\.mindscape\mindscape-release.keystore"
$env:MINDSCAPE_APK_KEY_ALIAS = "mindscape"
$env:MINDSCAPE_APK_STOREPASS = "<keystore 密码>"
pnpm android --release --targets arm64,arm,x86,x86_64
```

只想看将要执行什么、不动手：任何命令后加 `--dry-run`。
最终交付物是 `…-signed.apk`（脚本末尾会 `apksigner verify --print-certs` 打印证书指纹）。

## 1. 一次性准备：生成签名 keystore

**必须由项目维护者本人执行，且密钥放在仓库之外。** 脚本不会自动生成密钥 —— 凭证一旦丢失，
已装机的所有老用户都无法再覆盖升级（只能卸载重装，而空间数据在应用私有目录里，等于丢数据）。

```powershell
# 路径自己选，只要不在仓库里即可；这里跟桌面 updater 私钥（~/.tauri/mindscape.key）保持同一目录层级
keytool -genkeypair -v `
  -keystore "$env:USERPROFILE\.mindscape\mindscape-release.keystore" `
  -alias mindscape -keyalg RSA -keysize 2048 -validity 10000 -storetype PKCS12
```

- 命令会**交互式**询问 keystore 密码与 CN 等信息；密码不要在命令行里给出（会进 shell 历史）。
- ⚠️ **不要单独设 key password**。`apksigner` 只被喂了 `--ks-pass env:MINDSCAPE_APK_STOREPASS`，
  默认按「密钥密码 = keystore 密码」工作；`keytool` 不加 `-keypass` 时本来就取同一个值，
  一旦手滑设成两个密码，签名步骤会卡在交互提示上。
- 别名（`mindscape`）会作为 `MINDSCAPE_APK_KEY_ALIAS` 传给脚本，记下它。
- **备份三件套**（keystore 文件、别名、密码）到仓库和云盘之外的可靠位置。换 keystore = 放弃老用户。
- `.gitignore` 已补 `*.keystore` / `*.jks` 作为误放保险。
- `keytool` 来自 JDK 的 `bin`（`%JAVA_HOME%\bin` 通常已在 PATH 里）。

`mindscape-release.keystore`（APK 签名）与 `~/.tauri/mindscape.key`（自动更新包签名）互不替代：
前者决定「手机肯不肯覆盖安装」，后者决定「桌面客户端肯不肯下载这个更新包」。安卓**不走**自动更新，
所以用不到后者。

## 2. 每次发版

```bash
# 1. 同步版本号：src-tauri/tauri.conf.json 与 package.json 的 version，并在 CHANGELOG.md 记录改动

# 2. 桌面五项门禁（AGENTS.md 规则 ②）
pnpm typecheck && pnpm lint && pnpm test && pnpm build
cd src-tauri && cargo test

# 3. 正式包（§0 的三个环境变量已就绪）
pnpm android --release --targets arm64,arm,x86,x86_64

# 4. 把 app-universal-release-signed.apk 上传到 GitHub Release（tag = v + 版本号）
```

`pnpm android` 内部顺序固定为：`pnpm build` → cargo 交叉编译（每架构一次）→ 复制 `.so` 进
`jniLibs` → 写 `tauri.properties` 的 `versionName/versionCode` → `gradlew assemble*` →（release）
zipalign → apksigner sign → verify。前端产物 `dist/` 是在 **Rust 编译期**被 `generate_context!`
嵌进 `.so` 的，所以顺序不能调；只改了前端时加 `--skip-rust` 省一大截编译。

## 3. debug 包与 release 包：能不能互相覆盖

| | 谁签的 | 用途 | 产物 |
|---|---|---|---|
| debug | Android SDK 的 `~/.android/debug.keystore`（gradle 自动） | 真机测试、日志 | `app-arm64-debug.apk` |
| release | `mindscape-release.keystore` | 分发 | `app-universal-release-signed.apk` |

**两把不同的钥匙 → debug 与 release 之间不能覆盖安装**，换档必须先卸载，而卸载会清空
`<dataDir>/Mindscape/`（空间本体与导出都在应用私有目录）。所以真机测试的正确姿势是：
第一轮全程用 debug 包，要转 release 验证时**先把要留的空间导出**再卸载重装。

`applicationId` 固定为 `com.mindscape.canvas`，两种包共用同一个包名，不会并存两个图标。

## 4. versionCode 与升级规则

Android 判断「能不能覆盖」看的是整数 `versionCode`，算法与 Tauri CLI 一致（本机实测 `0.9.0` → `9000`）：

```
versionCode = major * 1_000_000 + minor * 1_000 + patch
```

脚本每次从 `src-tauri/tauri.conf.json` 读版本号重算并覆写 `app/tauri.properties`，
所以**只要版本号涨了，versionCode 一定跟着涨**。三条硬规则：

1. `versionCode` 只增不减 —— 旧码包装在新包之上会被系统拒绝；
2. 签名必须与已装版本一致 —— 不一致报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（见 §3）；
3. 版本号写在 `tauri.conf.json`，不要手改 `tauri.properties`（下次构建即被覆写）。

## 5. 分发：GitHub Release 侧载

移动端**没有自动更新通道**：`#[cfg(not(mobile))]` 让 updater / process 插件只在桌面挂载
（M1 第三步），能力表 `autoUpdate` 在安卓为 `false`，所以设置页里根本没有「检查更新」。
升级 = 重新下载新 APK 覆盖安装。

因此发布时：

- Release 正文里写明 APK 直链与「下载后直接安装即可覆盖升级，数据不会丢」；
- 只挂 `app-universal-release-signed.apk`（含四架构，单文件对所有真机可用）。
  给特定用户省流量时可以再挂 `app-arm64-release-signed.apk`（当代真机几乎都是 arm64）；
- ⚠️ 这个 Release 必须是「最新正式版」，不能是草稿或预发布 —— 桌面客户端的
  `releases/latest/download/latest.json` 也挂在同一个 Release 上，标成预发布会连带打断桌面自动更新；
- 用户侧首次安装需要允许「安装未知来源应用」，这是系统限制，不是应用问题。

装机前的最低验证：`docs/移动端真机测试清单.md` §1 冒烟 4 条 + §5 否定清单（后者专防桌面功能漏到手机上）。

## 6. 环境前提与 M0 踩过的坑

前提（`src-tauri/gen/android/` 缺失、三个环境变量缺任一项、release 少密钥或 build-tools 目录为空 ——
脚本都会在**动手执行任何命令之前**退出并指出缺哪项；只有 rustup target 没装这一类要等到 cargo 阶段才暴露）：

- JDK 17、Android SDK（`platform-tools` / `platform-36` / `build-tools`）、NDK r26d；
  `JAVA_HOME` / `ANDROID_HOME` / `NDK_HOME` 三个环境变量就位；
- rustup 四档安卓 target（`aarch64-linux-android` 等）；`CC/CXX/AR/LINKER` 由脚本按 target 自动注入；
- `src-tauri/gen/android/` 存在 —— 它是 `pnpm tauri android init` 的生成物且**不入库**。

已知坑：

1. **不要用 `pnpm tauri android build`**：M0 实测它在 Windows 上要开「开发者模式」（打包过程建符号链接），
   本机没开。`pnpm android` 就是为绕开它而固化出来的手动链路。
2. **gradle 里的 `rustBuild*` 任务必须排除**：它会回调 tauri CLI，又回到第 1 条。脚本已固定
   `-x` 掉全部 5 个（`universal` + 四架构），`android-build.test.mjs` 专门锁这一点。
3. **`gen/android/buildSrc/.../BuildTask.kt` 有两处本地手改**（npm 在 Gradle JVM 里解析不到，
   写死成 `C:\Program Files\nodejs\npm.cmd`）。`tauri android init` 重新生成后要重做 ——
   走本脚本时因为第 2 条已排除该任务，通常不会触发。
4. **签名配置不写进 `gen/android`**：那是生成物、不入库，往里塞 `signingConfig` 就是第三处
   「重新 init 即失效」的手改。所以 release 走外挂 `zipalign` + `apksigner`。
5. **Gradle 依赖走阿里云镜像**（`~/.gradle/init.gradle`，`google()` 在本机网络不可达）。
6. **debug 包很大（M0 实测 220 MB）属预期**：debug 不 strip，`universal` 又含四架构；
   release 侧 `[profile.release]` 有 `strip = true` / `lto`，体积会明显下来。别把体积当回归。
7. **`jniLibs` 目录里不止我们一个 `.so`**（插件的也在），脚本只覆盖 `libmindscape_canvas_lib.so`
   单文件，不整删目录 —— 手工清理时同理。

## 7. 口令处理

`MINDSCAPE_APK_STOREPASS` 只存在于当前进程的环境变量里；命令行参数中永远只出现字面量
`env:MINDSCAPE_APK_STOREPASS`，由 `apksigner` 自己去读环境变量。
`android-build.test.mjs` 断言 `resolveSigning()` 的返回体不含明文口令，且签名步骤的 `--ks-pass`
实参必须以 `env:` 开头 —— 防止以后有人图省事把密码拼进 argv（会进 `--dry-run` 输出和 shell 历史）。
