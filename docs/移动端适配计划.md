# 移动端适配计划（Android 先行）

> 2026-09-21 用户裁决启动移动端适配；**安卓先行**（iOS 后置）。
> 对应讨论：v0.9.0 发版后启动。本文档是唯一的执行依据，里程碑完成情况直接在 §4 表格打勾。

---

## 0. 现状盘点

### 0.1 架构红利（不需要改动的部分）

- **`core/` 纯逻辑层全平台无关**：数据 schema（zod）、命令系统（撤销/重做）、菜单配置中心、`meta` 扩展位、原子写、布局合并 —— 零平台依赖
- **画布交互基于原生 Pointer Events**：触屏同样派发 Pointer Events，手势层有现成底座（`canvas/interaction/` 12 个控制器各自独立）
- **D3 大图分级加载**：移动端内存问题的先手准备（缩小视图用缩略图，缓存在应用数据目录）
- **所有功能都有右键菜单入口**：不依赖键盘快捷键，移动端换成长按即可
- **运行时判断已存在**：`core/utils/runtime.ts` 的 `isDesktopRuntime()`
- **`clipboard-win` 已在 `cfg(windows)` 下**：Android target 不会编译它

### 0.2 桌面专属依赖（需要隔离 / 替换的 7 类）

| # | 依赖 | 现状 | 移动端处理 |
|---|---|---|---|
| 1 | `clipboard-win`（跨应用复制文件） | `cfg(windows)` 隔离 | 换 `tauri-plugin-clipboard-manager`（仅文本；移动端无「文件多格式」概念） |
| 2 | `open_with_default` / `reveal_in_explorer` | Rust 命令 | 前者走 opener 插件语义；后者移动端隐藏 |
| 3 | 自动更新（NSIS/MSI + latest.json） | updater 插件 | 移动端关闭（渠道分发无此机制） |
| 4 | 滚轮缩放 / Ctrl 框选 / 右键菜单 | 鼠标交互 | M2 手势重设计（最大工作量） |
| 5 | 悬停显示（文件名 / 分辨率 / 色号） | group-hover 纯 CSS | 触屏无悬停 → 改「选中即显示」 |
| 6 | 拖入文件 | `onDragDropEvent` | 换系统文件选择器 / 分享接收（复用 ingest 链路） |
| 7 | `%APPDATA%` 数据目录 | `dataDir()` | Tauri 移动端有对应目录；空间文件夹模型见 D3 裁决 |

## 1. 决策点

| # | 决策 | 结论 | 性质 |
|---|---|---|---|
| D1 | 目标平台 | **Android 先行**，iOS 后置（WKWebView 差异与开发者账号成本后置） | 用户裁决（2026-09-21「先做安卓就行」） |
| D2 | 分发方式 | **APK 侧载**（GitHub Release 附件），应用市场后置 | 默认采纳 |
| D3 | **空间文件夹模型（涉铁律①）** | **方案 A：移动端空间放应用数据目录，进出走显式导入 / 导出**（复用「导出布局 / 导入空间」链路）。桌面铁律不受影响，移动端是一次明确妥协；不用 Android SAF（机型兼容坑深、工程量大） | 默认采纳（建议项，随时可改） |
| D4 | 触屏交互范式 | **手势优先 + 兜底按钮**：单指按卡片=拖卡（沿用 4px 阈值）、单指按空白=平移、双指捏合=缩放（双指中点为锚点，10%~400% 沿用）、长按=右键菜单；框选改工具栏「选择模式」按钮 | 默认采纳 |

## 3. 里程碑

### M0 · 预研 spike（约 1 天）—— 环境搭建 + 编译验证

1. 装 JDK 17 / SDK / NDK / rustup targets（§2）
2. `pnpm tauri android init` 生成安卓壳工程
3. **全部 Rust 命令在 android target 下 `cargo check`**，产出「不可编译清单」（预计 clipboard.rs 等，已有 cfg 基础）
4. 空壳跑真机 / 模拟器；画布页性能基线（DOM 方案在移动 WebView 的首屏与拖动帧率）
5. **出口标准**：空壳可安装运行 + 不可编译清单 + 性能结论。若性能不达标，升级为架构级讨论（Canvas 化）再继续

### M1 · 平台抽象层（2–3 天）

- `lib.rs` 命令注册按平台条件化；`open_with_default` 等桌面命令在移动端返回「不支持」或直接不注册
- `runtime.ts` 增 `isMobileRuntime()` + **平台能力表**（哪些菜单 / 设置页隐藏：快捷键页、reveal_in_explorer、检查更新）
- capabilities 权限文件分平台；updater 在移动端静默关闭
- **验收：桌面五门禁零变化**（每里程碑结束必跑）

### M2 · 手势与交互（3–5 天，最大块）

- viewportController 双指捏合缩放（双指中点为锚点）+ 双指 / 单指平移
- 单指手势仲裁：卡片上=拖卡（4px 阈值沿用）、空白=平移
- 长按弹右键菜单（contextmenu 事件）；悬停信息（文件名 / 分辨率 / 色号）改「选中即显示」
- 框选 →「选择模式」工具按钮（D4）
- 便签 / 待办行内编辑在软键盘下的聚焦与滚动验证
- 架构红线不变：高频坐标直写 `transform`、不进 state（17.3 在触屏同样适用）

### M3 · UI 响应式（2 天）

- 顶栏 wrap、设置弹窗移动端全屏化、搜索浮层与空间列表自适应
- 中文文案常量表不动（架构红利）

### M4 · 移动能力接线（2–3 天）

- 文件选择器 / 分享接收替代拖入（复用 ingest 链路与落点规则）
- 剪贴板走 clipboard-manager 插件（仅文本）
- 打开原图接系统查看器
- 按 D3 方案 A 落地：空间数据目录模型 + 导入 / 导出接线

### M5 · 测试与发布（1–2 天）

- 真机测试清单（沿用 `docs/界面走查与截图清单.md` 的模式）
- 签名 keystore（**仓库外**，同 `mindscape.key` 惯例；`*.key` 已在 .gitignore）
- `tauri android build --apk` 脚本化 + 分发文档

**合计约 11–14 个工作日**的会话量。

## 5. 风险与红线

- **R1 铁律①在移动端的妥协**（D3 方案 A）—— 产品级决策，已在 §1 记录，可随时推翻重来
- **R2 桌面是已发布产品**：所有平台差异必须 cfg / 能力表隔离；**每里程碑结束重跑桌面五门禁**，桌面行为零变化
- **R3 移动 WebView 性能**：DOM 渲染方案在低端机表现未知，M0 spike 就测；不达标先升 D3 缩略图档位，再议 Canvas 化（另一个量级）
- **R4 网络环境**：Gradle / SDK / NDK 下载量大，走国内镜像；GitHub 通道不可用时 APK 分发走 api.github.com（既有 push-api-parity 同款通道）
- **R5 iOS**：后置；届时 WKWebView 差异（pointer events / 惯性滚动 / 安全区）另立清单

## 6. 第一版明确不做

iOS、平板双栏布局、移动端自动更新、移动端跨应用文件复制（系统限制，文本剪贴板即可）、桌面端外观变更。
