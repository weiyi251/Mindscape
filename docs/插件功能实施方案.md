## 0. 结论摘要

| 维度 | 结论 |
|---|---|
| 集成方式 | **插件靠宿主注入的 API 工作**，不自行 import 宿主。宿主通过 `activate(api)` 把能力交出去，所有注册自动打上 `pluginId` 归属 |
| 插件形态 | 推荐**可执行 JS 单文件插件**（`manifest.json` + `index.js`）；纯声明式能力包表达力太弱，做不出有意义的插件 |
| 加载方式 | Rust 读文本 → 走 Tauri asset 协议得到 URL → 动态 `import()`。**不引入任何新依赖** |
| 生命周期 | 发现 → 校验 → 安装 → 激活 → 停用 → 卸载，六态状态机；插件抛错只影响自己 |
| 状态存储 | `%APPDATA%\Mindscape\plugins.json`（fs 插件 scope 已覆盖，**无需改 capabilities**），原子写 |
| 生效机制 | registry 增 `registryVersion` + `disposePlugin(pluginId)`，UI 订阅版本号；菜单/渲染本就是即时查表，天然即时生效 |
| 界面 | 设置浮窗左侧页签加「插件」，左列表 + 右详情；`SETTINGS_PAGES` 加一项即可 |
| **硬前置** | **必须先拆 Board / Canvas**（Board 余 24 行、Canvas 顶死），否则埋 7 个钩子就撞守卫红线 |

## 1. 现状与需求的关键冲突

你上一轮选择的是「**编译期内置**」，而本次需求里的「**浏览并安装**」隐含插件来自应用外部。二者不能直接并存，需要明确边界：

- **编译期内置** = 插件代码随应用一起打包，用户**无法安装新插件**，只能启用/禁用。
- **浏览并安装** = 插件包在应用之外（本地文件 / 网络），需要「发现 → 下载或导入 → 落盘 → 加载」链路。

**建议的调和方式**（§9 待你确认）：**双来源并存**。

| 来源 | 进入方式 | 能否卸载 | 本期 |
|---|---|---|---|
| 内置插件（builtin） | 编译期打包，清单在 `src/plugins/builtinPlugins.ts` | 否（只能禁用） | ✅ 做 |
| 外部插件（external） | 用户从本地文件夹导入 / 手动放入插件目录 | 是 | ✅ 做 |
| 在线市场 | 远程 `index.json` + 下载 | 是 | ⏸ 预留接口，本期不做 |

这样「浏览」= 列出内置 + 已落盘的全部插件；「安装」= 从本地导入。零网络依赖，不需要服务器，也不违背 17 章依赖约束。

## 2. 插件与宿主应用的集成方式

### 2.1 插件包结构

```
%APPDATA%\Mindscape\plugins\<插件id>\
├── manifest.json      # 声明式元信息，宿主据此校验与展示
└── index.js           # 入口 ES module，导出 activate / deactivate
```

### 2.2 清单契约（`manifest.json`）

```jsonc
{
  "id": "com.example.hello",      // 反向域名风格，全局唯一
  "name": "示例插件",              // 展示名
  "version": "1.0.0",             // semver
  "description": "一句话说明插件做什么",
  "author": "作者名",
  "homepage": "https://...",      // 可选
  "apiVersion": 1,                // 宿主 API 版本，不匹配直接拒绝激活
  "minAppVersion": "0.5.0",       // 可选：要求的最低应用版本
  "main": "index.js"              // 可选，默认 index.js
}
```

用 **zod** 校验（项目已有依赖，无需新增）。校验失败 → 该插件标 `invalid` 并在列表里显示原因，**不阻断其他插件加载**。

### 2.3 入口契约（`index.js`）

插件是一个 **ES module**，必须导出 `activate`：

```js
export function activate(api) {
  api.registerCardType({ /* ... */ })
  api.registerMenuItem({ id: 'hello.greet', label: '打个招呼', action: () => api.log('hi') })
  api.registerHook('cardMoved', (payload) => { /* ... */ })

  // 返回的函数即 dispose 回调，停用时调用
  return () => { /* 清理定时器 / 订阅等 */ }
}
```

**为什么用「注入 api 参数」而不是让插件 `import` 宿主**：动态加载的插件模块没有可靠的模块解析基准，`import { registerCardType } from '@/core/...'` 必然失败。把 API 作为参数递进去，是唯一稳定且不需要打包工具参与的做法。

### 2.4 宿主 API 面（`PluginApi`）

```ts
export const PLUGIN_API_VERSION = 1

export interface PluginApi {
  apiVersion: number
  manifest: Readonly<PluginManifest>
  /** 插件自己的数据目录（%APPDATA%\Mindscape\plugin-data\<id>），宿主保证已创建 */
  dataDir: string
  /** 宿主注入的 React —— 否则插件写不出自定义卡片渲染 */
  react: { createElement: typeof createElement; Fragment: unknown }
  registerCardType(def: CardTypeDef): void
  registerMenuItem(item: MenuItem, cardType?: string): void
  registerHook(name: HookName, fn: HookFn): void
  /** 写进插件的运行日志，在「插件详情」里可见（排查加载失败用） */
  log(message: string): void
}
```

**关键实现细节**：`pluginHost` 在调用 `activate(api)` 之前，会把 `register*` 三个方法**包一层**，把每次注册登记进 `pluginRegistrations: Map<pluginId, Ticket[]>`。这样：

- 停用/卸载时可以**精确回收该插件的全部注册项**，不会误伤核心或其他插件；
- 「插件详情」页可以反查出「这个插件贡献了 N 个卡片类型、N 个菜单项、N 个钩子」。

这一步是当前 `pluginCenter` 最缺的东西 —— 现在的 `Map` 完全没有归属信息，**没有它就没有「禁用」可言**。

## 3. 加载与生命周期管理

### 3.1 状态机

```
   discovered ──install──▶ installed ──enable──▶ activating ──ok──▶ active
        │                      ▲                                  │
        │                      │                                  │
     invalid /            uninstall                          disable（先 deactivate
   incompatible             │                               再 dispose）
        │                      │                                  │
        ▼                      └──────────────▶ uninstalled ◀─────┘
     （列表可见，                                    ▲
       禁止启用）                          error ────┘（加载/激活抛错）
```

| 状态 | 含义 | UI 表现 |
|---|---|---|
| `invalid` | manifest 校验失败 | 灰显 + 红色原因行 |
| `incompatible` | `apiVersion` 不匹配或 `minAppVersion` 高于当前版本 | 灰显 + 「需要应用 ≥ x.y.z」 |
| `installed` | 已落盘、未启用 | 开关 OFF |
| `activating` | 激活中（防重入） | 开关显示「激活中…」且禁用 |
| `active` | 运行中 | 开关 ON + 绿点 |
| `error` | 激活失败 | 开关 OFF + 红字错误摘要 |
| `disabled` | 曾启用，用户手动关闭 | 开关 OFF |

### 3.2 各阶段实现

**① 发现（scan）**
- 内置：读编译期常量 `BUILTIN_PLUGINS`
- 外部：扫 `%APPDATA%\Mindscape\plugins\*\manifest.json`
- 合并去重：**内置优先**，id 撞车时忽略外部版本并提示一次（与 `cardTypes.ts` 的核心优先策略一致）

**② 校验**
- zod 解析 manifest
- `apiVersion !== PLUGIN_API_VERSION` → `incompatible`
- `minAppVersion` 比较需语义化版本比较 —— **不引入 `semver` 依赖**，自己写约 20 行比较函数（`compareVersion`，纯函数 + 单测），放在 `core/plugin/version.ts`

**③ 安装（install）**
- 用户通过 `dialog.open({ directory: true })` 选插件文件夹（plugin-dialog 已批准）
- 校验其 `manifest.json` → 复制到 `%APPDATA%\Mindscape\plugins\<id>`
- 同名已存在 → 提示「已安装 vX.Y.Z，是否覆盖」，用户确认才覆盖
- ⚠️ **zip 解压需要新增 Rust crate**（`zip`），超出 17.1 锁定的依赖清单 → 见 §9 决策 2

**④ 激活（activate）**
1. 读 `index.js` 文本（Rust 命令，见 §3.3）
2. `convertFileSrc(入口绝对路径)` 得到 asset URL → `import(/* @vite-ignore */ url)`
3. 取 `module.activate`；不存在 → `error`
4. 构造带归属登记的 `api` → 调 `activate(api)`
5. 保存返回的 dispose 回调
6. 任何一步抛错 → 回收本插件已注册项 → 置 `error` + 记录 message

**⑤ 停用（disable）**
1. 调插件自己的 `deactivate()`（若导出）
2. 调激活时返回的 dispose 回调
3. `disposePlugin(pluginId)` 回收注册项
4. 状态 → `disabled`

**⑥ 卸载（uninstall）**
- 若 active 先 disable → 删插件目录 → 从 `plugins.json` 移除记录
- **数据一律保留**：卡片的 `meta`、`plugin-data/<id>` 目录都不删（守铁律③「不静默删除」）
- 用了该插件卡片类型的卡片**不删**，退化为 `file` 兜底渲染（`renderCard` 已有兜底），UI 必须提前说明

**⑦ 应用退出**
- 逐个调 `deactivate()`；不落盘任何临时态

### 3.3 动态加载的技术路线

Tauri v2 下有两种可行做法，**推荐 asset 协议**：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **asset 协议（推荐）** | Rust 无需新命令，直接 `convertFileSrc(absPath)` 得到 `http://asset.localhost/...` → `import()` | **支持插件内部相对 import**（多文件插件可用）；`assetProtocol.scope` 已是 `["**"]`，无需改配置 | 依赖 asset 协议，跨源但 `csp: null` 不拦 |
| Blob URL | Rust 读文本 → `new Blob([code])` → `URL.createObjectURL` → `import()` | 完全可控，可做代码注入/校验 | **无法解析相对导入** → 插件必须单文件 |

已核实的前提：`tauri.conf.json` 中 `security.csp` 为 `null`、`assetProtocol.enable` 为 `true`、`scope` 为 `["**"]` —— **现有配置直接支持 asset 路线，不用改任何 Tauri 配置**。

**Vite 构建注意**：动态 URL 导入必须写 `import(/* @vite-ignore */ url)`，否则 Vite 会尝试静态分析并报错。

**非桌面环境降级**：`pnpm dev` 在浏览器里跑时没有 Tauri 后端，插件功能必须整体降级（复用 `assertDesktopRuntime()` 的同款做法），列表显示「插件功能仅在桌面版可用」。

## 4. 启用状态的存储与生效机制

### 4.1 存储位置与结构

**`%APPDATA%\Mindscape\plugins.json`**

```jsonc
{
  "version": 1,
  "plugins": {
    "com.example.hello": {
      "enabled": true,
      "installedAt": "2026-09-14T00:13:00+08:00",
      "source": "external"          // builtin | external
    }
  },
  "settings": { "riskAcknowledged": true }
}
```

选择的理由：
- `$DATA/Mindscape/**` **已在** capabilities 的 `fs:scope` 白名单里 → **零配置改动**（与 `spaces.json` / `layouts/` 同一条路）
- 不放 localStorage：插件状态需要可备份、可手改排查，且要跟插件目录待在一起
- 不放 layout：插件启用状态是**应用级**而非空间级，放进 layout 会导致每个空间各存一份
- 落盘沿用 **防抖 + 原子写**（`.tmp` + rename），与 `spaces.json` 完全一致
- 版本策略同 layout：`version > PLUGINS_DATA_VERSION` → 只读、不写盘

### 4.2 生效机制（本次设计的技术核心）

现状分析：

| 读取点 | 是否即时生效 | 原因 |
|---|---|---|
| 右键菜单 | ✅ 天然即时 | `buildCardMenuFor()` 在每次打开菜单时调用，即时查表 |
| 卡片渲染 | ✅ 天然即时 | `renderCard()` → `getCardTypeDef()` 即时查表 |
| **React 重渲染** | ❌ | registry 是普通模块级 `Map`，变了 React 不知道 |
| **动作注销** | ❌ | `registerAction` 在 Board 的 `useEffect` 里一次性登记，无注销调用方 |

所以要做三件事：

**① `pluginCenter` 扩展（核心改动）**

```ts
// 新增：注册项归属 + 版本号
let registryVersion = 0
const registrations = new Map<string, Set<string>>()   // pluginId → 注册项键

export function registryVersionNow(): number
export function disposePlugin(pluginId: string): void   // 回收该插件全部注册项，bump 版本
```

每次 `register*` / `disposePlugin` 都 `registryVersion += 1`。

**② 新增 `pluginsStore`（zustand）供 UI 订阅**

```ts
interface PluginsState {
  descriptors: PluginDescriptor[]   // 列表（含状态）
  version: number                   // 与 registryVersion 同步，供组件订阅
  install(dir: string): Promise<void>
  setEnabled(id: string, on: boolean): Promise<void>
  uninstall(id: string): Promise<void>
  reload(): Promise<void>
}
```

组件（设置页、Board 的菜单构建处）订阅 `version`，一次 bump 触发一次重渲染。

⚠️ **红线约束**：**绝不能**把这个订阅引进画布高频路径。卡片渲染仍走 `renderCard` 即时查表；禁用插件后由 `pluginsStore` 主动 bump 一次触发整体刷新即可。

**③ 真正埋钩子（当前零调用）**

7 个钩子必须落到真实触发点：

| 钩子 | 埋点位置 | 注意 |
|---|---|---|
| `cardSelected` | `canvas/Canvas.tsx` 选中态提交处 | 只在提交时发，不跟指针移动 |
| `cardMoved` | Board 拖拽**落点提交**时 | ⚠️ **绝不能**在拖拽过程中发（违反 17.3 高频红线） |
| `cardCreated` | `addCards` 成功后 | |
| `cardRemoved` | `removeCards` 后 | |
| `partitionRenamed` | `renamePartition` 后 | |
| `spaceOpened` / `spaceClosed` | Board 挂载/卸载、切空间 | |

同时把 `HookFn = (payload: unknown) => void` 改为**按钩子定形的泛型映射**（`HookPayloadMap`），否则插件作者拿到 `unknown` 无法使用。

### 4.3 一个必须提前说清的行为

**禁用插件后，画布上那些插件类型的卡片会怎样？**

答案：**卡片不删、数据不丢，渲染退化为「文件」样式**（走 `CORE_CARD_TYPE_DEFS.file` 兜底）。

这是有意设计的（守铁律③），但**必须在 UI 上明说**，否则用户会以为"数据坏了"。文案建议：

> 停用后，该插件创建的卡片会以普通文件样式显示；卡片与数据不会被删除，重新启用即恢复。

### 5.3 详情面板内容

- **描述全文**

### 5.4 交互规则

| 场景 | 行为 |
|---|---|

| 搜索 | 按名称 / 描述 / 作者过滤，纯前端 |
| 空状态 | 「还没有安装任何插件」+ 引导按钮 |
| 无搜索结果 | 「没有匹配的插件」 |
| 非桌面环境 | 整页替换为「插件功能仅在桌面版可用」 |

## 10. 已知风险与需留意之处

1. **插件代码与宿主同权限** —— 动态插件能调 Tauri `invoke`，理论上可读写 `%APPDATA%\Mindscape` 与用户空间文件夹。这是选择 (a) 路线的固有代价，只能靠「明示风险 + 只装可信来源」缓解。若将来要收紧，改造点在 `pluginLoader`（换成 Worker 沙箱 + postMessage）。
2. **Blob 路线不支持相对导入** —— 若将来需要多文件插件，必须用 asset 协议路线（本方案推荐的就是这条，所以已经规避）。
3. **Vite 动态导入** —— 必须写 `/* @vite-ignore */`，否则打包期报错。
4. **HMR 重复激活** —— 开发期插件模块会被重复执行，激活前必须先 dispose 同 id，否则注册项叠加（`pluginCenter` 现在的「重复注册覆盖 + warn」只能兜底，不解决归属叠加）。
5. **卡片类型禁用后的渲染退化** —— 必须有明确 UI 说明（§4.3），否则用户会误判为数据损坏。
6. **内置与外部插件 id 撞车** —— 内置优先 + 提示一次（复用 `cardTypes.ts` 已有的 `warnedDuplicateTypeIds` 去重套路）。
7. **主题一致性** —— 插件若自带 UI，架构守卫规则 3（配色只走语义 token）**管不到 `src/` 之外的代码**，只能在文档与 API 说明里约定；详情页可以提供一段「插件开发须知」。
8. **应用版本比较** —— 不引入 `semver` 依赖，自己写约 20 行 `compareVersion`（纯函数 + 单测）。
9. **`pluginsStore` 与画布订阅隔离** —— 绝不能把版本号订阅引进高频渲染路径（§4.2 红线）。
