## 0. 装包、看日志

| 要做的事 | 命令 / 入口 |
|---|---|
| 构建 debug APK | `pnpm android`（脚本 `scripts/android-build.mjs`，默认 arm64 debug）→ `src-tauri/gen/android/app/build/outputs/apk/arm64/debug/app-arm64-debug.apk`。四档齐出（分发口径）：`pnpm android --universal` |
| 装上 / 覆盖安装 | `adb install -r app-arm64-debug.apk`（**一定要 `-r`**，裸 `adb install` 会先卸载、把已建的空间清掉） |
| 看 Rust 侧报错 | `adb logcat -s tauri:V chromium:V`（invoke 失败的中文 Err 从这里出，比界面上那句完整） |
| 调 WebView | Chrome 打开 `chrome://inspect`（**只有 debug 包可调试**） |
| 看应用私有目录 | `adb shell run-as com.mindscape.canvas ls -R /data/data/com.mindscape.canvas/files/Mindscape`（debug 包能直接进；包名 = `tauri.conf.json` 的 identifier，**发布后永不能改**） |
| 找不到设备 | `adb devices` 列表空 = 手机没开「开发者选项 → USB 调试」；列出但 `unauthorized` = 手机上没点「允许调试」 |
| **点开闪一下就退出** | 先怀疑**包里根本没打界面**：`tauri/custom-protocol` 这个 cargo feature 没开时，`generate_context!` 不把 `dist/` 嵌进 `.so`，运行时改连本机 1420 的 dev server —— 手机上当然连不上。`pnpm android` 已固定带这个 feature（`android-build.test.mjs` 有断言）；核对：`pnpm android --dry-run` 看 cargo 那行有没有 `--features tauri/custom-protocol`，或直接扫 `.so` 里有没有 `assets/index-` 字样。完整推理记在 `docs/移动端发布流程.md` §6 第 1 条 |
| **页面显示「脚本运行出错 / Unexpected token ?」** | 这是**内核太老**，不是应用 bug。先看兜底页打出来的 `UA:` 里的 `Chrome/xx`（2026-09-21 之后有；之前靠 `adb shell dumpsys webviewupdate` 查）。**硬底线 Chrome 76**（产物里 `??` 出现 160 处，76 才认），**推荐 ≥ 87**（CSS 用了 `inset` 87 / flex `gap` 84，低于此布局会错位但不会报错）。实测：联想模拟器（Android 9）的 WebView 提供程序是 `com.android.chrome 68.0.3440.70` → **不可用**，为什么不降 `build.target` 迁就它见 `docs/移动端发布流程.md` §6 第 9 条 |
| 用模拟器测 | 先 `adb shell getprop ro.product.cpu.abi` 看架构，再 `pnpm android --targets x86_64`（默认只出 arm64；x86_64 机器上跑 arm64 靠 ARM 转译，慢且会多出怪问题） |

**第 0 项：先确认平台判定生效，否则后面全是白测。**
打开设置面板 —— 只应该看到「插件」一页。若「快捷键」「更新」两页还在，说明 `isMobileRuntime()` 没读到 Android 的 UA
（`core/utils/runtime.ts`），全项目的移动端分支都不会走，**先停下改这一处**（⚠️ 某些国产 ROM 的 WebView 会改 UA，
需要按真机 UA 字符串补正则）。
⚠️ 2026-09-21 第一轮真机实际先撞的是**上一条**（装得上、点开黑屏闪退），根因是 cargo 缺 `tauri/custom-protocol`
—— 症状像崩在原生层，其实是包里没打界面；与签名、`.so` 加载、UA 判定都无关。
⚠️ 同日第二轮（模拟器）撞的是**上上条**：内核 Chrome 68 解析不了产物里的 `??`，连第 0 项都没开始测。
**所以开测前先 `adb shell dumpsys webviewupdate` 看内核版本**，比测一半发现全是假 bug 划算。

## 5. 否定清单：这些东西在安卓上**不该出现**

出现了就是 bug（全部由 `core/system/platformCapabilities.ts` 那 9 个能力位控制）：

| 不该出现 | 出现位置 | 对应能力位 |
|---|---|---|
| 「快捷键」设置页、「更新」设置页 | 设置面板 | `keyboardShortcuts` / `autoUpdate` |
| 「检查更新」「有新版本」任何提示 | 启动 / 设置 | `autoUpdate` |
| 卡片菜单里的「打开原图」 | 长按卡片 | `openWithSystemApp` |
| 插件页的「打开插件目录」按钮 | 设置 → 插件 | `openWithSystemApp` |
| 「在文件夹中定位」相关提示或降级 | 打开失败时 | `revealInExplorer` |
| 「拖入文件」的引导条 / 拖拽响应 | 画布 | `dragAndDropImport` |
| 任何依赖 hover 才显示的信息 | 卡片 chip | `pointerHover` |
| 跨应用**复制文件**（粘到相册/文件管理器里） | 长按复制 | `systemClipboardFiles` ❌ 设计上不做 |

反向也要查：**桌面上这些必须一个都不少**（红线 R2）。改完移动端分支后请在桌面 `pnpm tauri dev` 里扫一眼同一批入口。

## 7. 已知取舍（❌ 不是 bug）

1. **跨应用复制/粘贴文件**不做 —— `clipboard.rs` 四个命令只有 Windows 分支（CF_HDROP），安卓没有对应概念。
2. **「打开原图」看系统图库**不做 —— opener 插件在安卓三条通道全断（见计划 §4 M4 ⑤），要做得在 `gen/android` 加 FileProvider + 自定义 Kotlin。
3. **分享接收**（从相册「分享到 Mindscape」）不做 —— 同上要改 Kotlin 生成物；第一版由「导入文件」按钮覆盖同一场景。
4. **自动更新**不做 —— APK 侧载没有更新渠道。**升级方式 = 用同一个签名密钥重新打包、`adb install -r` 覆盖安装**（详见 `docs/移动端发布流程.md`）。
5. **release 包默认不可调试** —— 排查问题时请装 debug 包（`pnpm android`）。
6. **iOS 不做** —— D1 裁决安卓先行，WKWebView 的差异（pointer events / 惯性滚动 / 安全区）另立清单。
7. **画布上的系统级手势**（全面屏返回、通知栏下拉）与我们的单指平移可能抢手势 —— 属于 ROM 行为，先记录机型再判。
