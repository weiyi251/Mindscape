## 0. 五分钟做一个最小插件

### 0.1 路线选择

| | 内置插件（builtin） | 外部插件（external） |
|---|---|---|
| 代码位置 | 仓库内 `src/plugins/<名称>/` | `%APPDATA%\Mindscape\plugins\<插件 id>\` |
| 形态 | TypeScript 源码，编译进应用 | 纯 JS 文件，运行时动态 import |
| 分发 | 随应用发布 | 用户自己拷贝目录 |
| 默认状态 | **首次登记即启用** | 登记后为「已安装」，需用户手动启用 |
| 能否卸载 | 不能（只能停用） | 能 |
| 能否重新加载 | 不能（随应用更新） | 能（`reload`，用户换文件后点一下生效） |
| 适用 | 第一方能力、需要 TS 类型与单测 | 用户自写自用、第三方分发 |

**开发期强烈建议先走内置路线**：有类型检查、有单测、有完整调试体验。
功能稳定后再考虑抽成外部插件分发。

### 0.2 内置插件：最小可用版本

```
src/plugins/hello/
  index.ts       元信息 + activate（唯一出口）
  text.ts        中文文案常量
  hello.ts       纯逻辑（可选，但只要有逻辑就必须有 hello.test.ts）
  index.test.ts  同名测试（守卫规则 6 强制）
```

```ts
// src/plugins/hello/text.ts —— 中文文案集中一处，且**不 import 任何模块**
//（这样它永远不会反向依赖别的模块，从根上避免循环依赖）
export const HELLO_TEXT = {
  pluginName: '问候',
  pluginDescription: '在画布空白右键菜单里加一个「打个招呼」。',
  menuLabel: '打个招呼…',
} as const
```

```ts
// src/plugins/hello/index.ts
import type { BuiltinPluginDescriptor } from '@/core/plugin/types'
import { HELLO_TEXT } from './text'

/** 插件 id：小写反向域名风格，至少两段。它同时是安装目录名、meta 命名空间、plugins.json 的键 */
export const HELLO_PLUGIN_ID = 'example.hello'
export const HELLO_MENU_ITEM_ID = 'example.hello.greet'

export const helloPlugin: BuiltinPluginDescriptor = {
  manifest: {
    id: HELLO_PLUGIN_ID,
    name: HELLO_TEXT.pluginName,
    version: '1.0.0',
    description: HELLO_TEXT.pluginDescription,
    author: '你的名字',
    main: 'index.js', // 内置插件不经动态 import，这个字段只为与外部插件保持同一份清单形状
  },

  activate(api) {
    api.registerCanvasMenuItem({
      id: HELLO_MENU_ITEM_ID,
      label: HELLO_TEXT.menuLabel,
      action: (ctx) => {
        // ctx.spacePath = 当前空间文件夹绝对路径
        console.info('你好，当前空间：', ctx.spacePath)
      },
    })
  },
}
```

最后**登记一行**：

```ts
// src/plugins/builtinPlugins.ts
import { helloPlugin } from './hello'
export const BUILTIN_PLUGINS: BuiltinPluginDescriptor[] = [
  colorCardPlugin,
  helloPlugin, // ← 就这一行
]
```

跑门禁：`pnpm typecheck && pnpm lint && pnpm test && pnpm build`。启动应用 → 画布空白处右键，
菜单里就有「打个招呼…」。

### 0.3 外部插件：最小可用版本

> 仓库里有一个**官方示例外部插件** `docs/examples/example.dated-note/`（「日期便签」：
> 画布右键创建写好今天日期的便签），自带 `README.md`（安装步骤 + 真机验证清单）——
> 把整个文件夹复制到 `%APPDATA%\Mindscape\plugins\` 即可体验，改它就是你的第一个插件。

```
%APPDATA%\Mindscape\plugins\example.hello\
  manifest.json
  index.js
```

```json
{
  "id": "example.hello",
  "name": "问候",
  "version": "1.0.0",
  "description": "在画布空白右键菜单里加一个「打个招呼」。",
  "author": "你的名字",
  "main": "index.js"
}
```

```js
// index.js —— 必须是 ES module，且必须导出 activate
export function activate(api) {
  api.registerCanvasMenuItem({
    id: 'example.hello.greet',
    label: '打个招呼…',
    action(ctx) {
      console.info('你好，当前空间：', ctx.spacePath)
    },
  })
}

// 可选：宿主回收注册之后调用，用来清理插件自己的外部资源（定时器、订阅、文件句柄…）
export function deactivate() {
  console.info('再见')
}
```

然后打开 **设置面板 → 插件** → 点「刷新」，列表里出现「问候」→ 点「启用」。

> ⚠️ 目录名建议与 `manifest.id` 一致（不一致时宿主以 manifest 为准，但安装目录名会用来
> 定位这个插件）。
> ⚠️ 清单里的 `main` **只能是纯文件名**（见 §2.2），不能写 `dist/index.js`。

## 1. 心智模型：插件到底是什么

### 1.1 一条铁律

> **插件不 import 宿主。** 插件只使用宿主在 `activate(api)` 里注入的 `api` 对象。

原因不是风格洁癖，而是机制要求：宿主必须知道「哪些注册属于哪个插件」，才能实现
**停用**（回收注册）与**卸载**（回收注册 + 删目录）。如果插件自己
`import { registerCardType } from '@/core/registry/pluginCenter'`，注册表就失去了归属信息，
停用这个插件就无从下手。

具体到代码：

```ts
// ❌ 绝对不要这么写
import { registerCanvasMenuItem } from '@/core/registry/pluginCenter'
registerCanvasMenuItem({ ... })

// ✅ 只能这么写
export function activate(api) {
  api.registerCanvasMenuItem({ ... })
}
```

同理，插件**不要 import 别的插件** —— 插件之间的通信应当通过卡片 `meta` 或钩子。

> 可以 import 的：`@/core/*` 里的**纯类型与纯数据契约**（如 `@/core/plugin/types`、
> `@/core/board/cardMeta` 的 `HOVER_LABEL_META_KEY`）。这些是「共享词汇表」，不是能力。
> 判断标准：**import 它是为了拿一个能力（能做事），还是为了拿一个约定（对齐数据形状）？**
> 后者可以，前者不行。

### 1.2 生命周期

宿主对每个插件跑这条流水线（实现见 `core/plugin/pluginHost.ts`）：

```
发现 ──→ 校验 ──→ 激活 ──→ 运行 ──→ 停用 ──→ 卸载
```

对应六个状态（`core/plugin/types.ts` 的 `PluginState`）：

```
discovered ──校验失败──→ invalid
     └──校验通过──→ installed ──启用──→ active
                                  ↑        │
                                  └─停用── inactive
     任一环节抛错 ──→ error（注册已回收，detail 里带中文原因）
```

关键行为：

| 行为 | 发生了什么 |
|---|---|
| **启用** | 内置：直接调 `activate(api)`；外部：`convertFileSrc` + 动态 `import` → 调 `activate(api)` |
| **停用** | 先 `disposePlugin(id)` 回收该插件的**全部注册**，再调插件的 `deactivate()`（若有） |
| **卸载** | 停用 + 递归删除安装目录，**插件配置保留** |
| **重新加载** | 重读磁盘上的 `manifest.json` 与入口文件；原本在跑就重新启用一次 |
| **刷新** | 重新扫描外部插件目录 |

**失败隔离**：`activate` 抛错时，宿主会先回收它半途注册的内容，再把状态置为 `error`，
其他插件与宿主完全不受影响。用户修好文件后可以直接点「重试」（`error` 状态允许启用）。

**因此**：`activate` 里注册了三条、第四条抛错 → 前三条不会残留。可以放心地写「先注册再校验」的代码。

### 1.3 启动顺序

`src/plugins/bootstrap.ts` 在 `main.tsx` 里被调用，且**刻意不 await**：

```ts
void bootstrapPlugins()
```

原因：`init()` 有磁盘 I/O，阻塞首帧只是让启动变慢。内置插件只注册菜单项，
而菜单是**右键时才查表组装**的，晚一拍注册不会漏项。

> 如果你要注册**卡片类型**（渲染时查表，必须首帧前就位），需要把 `await` 加回来 ——
> 但目前没有插件这么做。

## 2. 包结构规范

### 2.1 内置插件：一个插件一个文件夹

```
src/plugins/
  index.ts             barrel —— 应用接触插件系统的唯一入口（只做转出）
  builtinPlugins.ts    内置插件清单（**加插件就改这里一行**）
  bootstrap.ts         启动引导（登记 + 初始化）
  <插件名>/            一个插件一个文件夹
    index.ts(.tsx)     元信息 + activate（唯一出口）
    text.ts            中文文案常量（不 import 任何模块）
    <纯逻辑>.ts         参数 / 校验 / 格式化 …
    <纯逻辑>.test.ts    同名测试（强制）
    <界面>.tsx          交给宿主挂载的 React 组件
  demo/                示例插件（仅测试调用，不在清单里）
```

文件命名约定：

| 文件 | 放什么 | 约束 |
|---|---|---|
| `index.ts` / `index.tsx` | `manifest` + `activate` + 可选的 `deactivate` | 导出 `BuiltinPluginDescriptor`；被 `builtinPlugins.ts` 引用 |
| `text.ts` | 用户可见的中文文案 | **不 import 任何模块**（防循环依赖）；不含 hex 字面量 |
| 其余 `.ts` | 纯函数 / 纯数据 | **每个都要有同名 `.test.ts`**（守卫规则 6） |
| `.tsx` | React 界面 | 渲染层可进 `UNTESTED_ALLOWLIST`，但里面的判断必须来自已测的纯函数 |

界面代码**必须留在插件自己的文件夹里**：插件通过 `api.ui.openDialog(title, render)` 把
一个 render 函数交给宿主，由宿主挂载。宿主完全不认识「色卡」「问候」这些概念。

### 2.2 外部插件：清单契约

`manifest.json` 过 zod 校验（`core/plugin/manifest.ts`），字段如下：

| 字段 | 必填 | 约束 |
|---|---|---|
| `id` | ✅ | 小写反向域名风格，至少两段：`/^[a-z0-9][a-z0-9-]*(?:\.[a-z0-9][a-z0-9-]*)+$/`<br>如 `com.example.hello`、`mindscape.color-card` |
| `name` | ✅ | 非空 |
| `version` | ✅ | 非空字符串（建议语义化版本） |
| `description` | | 默认 `''` |
| `author` | | 默认 `''` |
| `main` | | 默认 `index.js`；必须是**纯文件名**且以 `.js` / `.mjs` 结尾：`/^[A-Za-z0-9_][A-Za-z0-9_.-]*\.m?js$/` |

**为什么 `main` 不许含路径分隔符**：入口路径由宿主拼进 `convertFileSrc()`，
若允许 `../` 就等于开放了路径穿越。这是前端侧的最后一道安全边界。

入口模块必须导出：

```ts
export function activate(api: PluginHostApi): void | Promise<void>
export function deactivate?(): void | Promise<void>   // 可选
```

`activate` 缺失 → 启用失败，状态置 `error`，`detail` 显示
「插件「xxx」的入口 index.js 未导出 activate(api) 函数」。

> 外部插件是**不可信输入**：用户可以手改、复制出错、或者它本来是给别的工具用的。
> 所以清单校验失败不会崩，只会把这个插件标成 `invalid`（不可启用），
> 用户能在设置页看见原因并删掉它。清单缺失时宿主用目录名当 id，好让用户能找到它。

### 2.3 多文件外部插件

动态加载走 `convertFileSrc()` + 原生 `import(/* @vite-ignore */)`，
入口文件可以用相对路径 import 同目录的其他 `.js`（asset 协议能取到它们）。
**接入零 Tauri 配置改动** —— `tauri.conf.json` 的 `csp=null` 与
`assetProtocol.scope=["**"]` 已具备，`capabilities` 的 `fs:scope` 含 `$DATA/Mindscape/**`。

仓库内**没有** zip 导入与在线市场（方案未采纳）。装插件就是拷目录 + 点刷新。

## 3. API 全量参考

`activate(api)` 收到的对象形状（`core/plugin/types.ts` 的 `PluginHostApi`）：

```
api
├── pluginId                    只读，当前插件 id
├── registerCardType            注册卡片类型
├── registerMenuItem            注册卡片右键菜单项
├── registerCanvasMenuItem      注册画布空白右键菜单项
├── registerHook                注册生命周期钩子（⚠️ 见 3.4）
├── ui                          对话框
├── fs                          写文件 / 选目录
├── board                       当前空间 / 在画布上建卡
└── config                      插件私有配置
```

### 3.1 `api.registerCardType(def)`

新增一种卡片类型（渲染时按 `card.type` 查表）。

```ts
api.registerCardType({
  type: 'example.swatch',       // 与 card.type 对应；不能为空
  render: ({ card, selected }) => <div>…</div>,
  menu: [],                     // ⚠️ 见下方说明
  defaultSize: { w: 160, h: 160 },
})
```

| 参数 | 说明 |
|---|---|
| `type` | 类型标识。**与核心三类型（`image` / `file` / `note`）同名会被忽略**并打一条 warn（核心优先） |
| `render(props)` | 渲染函数，`props = { card, selected, noteEditing? }` |
| `menu` | 保留字段（满足 17.8 的接口形状）。**当前不参与菜单聚合** —— 加卡片菜单项请用 `registerMenuItem` |
| `defaultSize` | 新建该类卡片时的默认尺寸 |

`CardRenderProps`：

| 字段 | 说明 |
|---|---|
| `card` | 卡片数据（含 `meta`、`note`、`filePath`、`x/y/w/h`） |
| `selected` | 是否选中，渲染层据此画选中框 |
| `noteEditing` | 便签行内编辑中。此时**不要再画正文 / 占位文字** —— 会透过透明 textarea 与用户输入重叠 |

**渲染层的三条硬约束**：

1. **不要给卡片盒子写尺寸**。外层容器（`canvas/Card.tsx`）已经决定了位置与大小，
   你的 render 只管填内容。
2. **高频坐标不进 React state**。拖拽 / 缩放过程中直接写 `style.transform`，
   松手才 commit 一次 state（17.3 红线）。
3. **悬停态用纯 CSS**。卡片根元素带 `group` 类，你要做悬停淡入就用
   `opacity-0 group-hover:opacity-100`，**不要**用 `onMouseEnter` + state。

### 3.2 `api.registerMenuItem(item, cardType?)`

给**卡片**的右键菜单加一项。

```ts
api.registerMenuItem(
  {
    id: 'example.exportImage',
    label: '导出为图片…',
    appliesTo: (card) => card.type === 'image' && card.w > 200, // 可选：更细的过滤
    action: (ctx) => {
      // ctx.card 一定存在（这是卡片菜单）
      console.info(ctx.card?.id, ctx.spacePath)
    },
  },
  'image', // 可选：限定只有该类型的卡片显示
)
```

`MenuContext`：

| 字段 | 何时有值 |
|---|---|
| `spacePath` | 总是有（当前空间文件夹绝对路径） |
| `card` | 卡片菜单里有；画布空白菜单里为 `undefined` |
| `partition` | 分区框菜单里有 |
| `connection` | 连线菜单里有 |

**顺序与冲突**：最终菜单 = 核心项（按配置顺序）+ 插件项（按注册顺序）。
若插件注册的 `id` 与核心项同名，**保留核心**并打 warn（防止插件覆盖核心行为）。

### 3.3 `api.registerCanvasMenuItem(item)`

给**画布空白处**的右键菜单加一项。这是画布级动作的标准入口（色卡插件就用它）。

```ts
api.registerCanvasMenuItem({
  id: 'example.hello.greet',
  label: '打个招呼…',
  action: (ctx) => api.ui.openDialog('问候', () => <HelloDialog api={api} spacePath={ctx.spacePath} />),
})
```

菜单渲染时，插件项被插在「创建类动作」与「撤销 / 重做」之间，第一项前自动加一条分隔线，
`id` 会被加上 `plugin:` 前缀（避免与核心项如 `canvas.createNote` 撞键）。菜单是
**即时查表**组装的 —— 插件一启用 / 停用，菜单立刻跟着变。

### 3.4 `api.registerHook(name, fn)`

七个钩子名与载荷形状（`HookPayloadMap`）：

| 钩子 | 载荷 | 语义 |
|---|---|---|
| `cardSelected` | `{ cardId: string; selectedIds: string[] }` | 选中集合变化（含取消选中） |
| `cardMoved` | `{ cardId: string; x: number; y: number }` | 单张卡片移动**结束**（松手提交一次） |
| `cardCreated` | `{ card: Card }` | 新增卡片（新建 / 拖入 / 粘贴 / 插件建卡） |
| `cardRemoved` | `{ cardIds: string[] }` | 卡片被移除（移入 `_已移除`，文件仍在硬盘） |
| `partitionRenamed` | `{ partitionId: string; previousName: string; nextName: string }` | 分区框改名成功 |
| `spaceOpened` | `{ spacePath: string }` | 进入某个空间 |
| `spaceClosed` | `{ spacePath: string }` | 离开空间（返回列表） |

```ts
api.registerHook('cardMoved', (payload) => {
  const { cardId, x, y } = payload as HookPayloadMap['cardMoved'] // 用 Map 安全收窄
  console.info(cardId, x, y)
})
```

**触发点（2026-09-20 已全部埋点）**：

| 钩子 | 触发位置 | 语义细节 |
|---|---|---|
| `cardSelected` | 画布选中集合变化时 | 集合真正变化才触发；`cardId` = 本次最后选中的卡片，清空时为空串 |
| `cardMoved` | 拖动松手提交时 | 拖拽过程不触发，松手一次；redo 把卡片移回同位置也触发 |
| `cardCreated` | addCards 命令生效时 | 新建 / 拖入 / 粘贴 / 插件建卡共用；每张卡一次 |
| `cardRemoved` | 移除命令成功后 | 只上报真正移走的卡片；整体失败不触发 |
| `partitionRenamed` | 硬盘文件夹改名成功后 | 名字一定已经落盘 |
| `spaceOpened` | 空间加载成功后 | Board 挂载完成 |
| `spaceClosed` | 离开空间（Board 卸载）时 | 与 `spaceOpened` 成对出现 |

两条通用语义：**undo 不触发**任何钩子（`cardCreated` 的 redo 会再次触发 —— 卡片确实
重新出现了）；单个回调抛错不影响其他回调。

已注定的两条行为：
- 单个回调抛错**不会影响其他回调**（`emitHook` 逐个 try/catch）；
- `emitHook` 返回实际被调用的回调数量（调试用）。

### 3.5 `api.ui`

| 方法 | 说明 |
|---|---|
| `openDialog(title, render)` | 打开插件自己的对话框。`render` 是 `() => ReactNode`，**每次打开时调用** |
| `closeDialog()` | 关闭当前插件对话框 |

宿主负责：套模态框、Esc 关闭、点遮罩关闭、把 `render()` 的结果挂进 React 树。
插件负责：交出 render 函数、在自己界面里自己画按钮。

**约定**：
- 插件**不要** import 宿主的弹窗组件（那样插件代码就散到宿主里了）；
- 用 `api.ui.closeDialog` 关闭按钮，不要自己操纵 DOM；
- 界面里的每个判断都应来自已单测的纯函数（渲染层本身测不了，本项目不引入 jsdom）。

### 3.6 `api.fs`

| 方法 | 签名 | 说明 |
|---|---|---|
| `writeBytes` | `(destDir, fileName, bytes: Uint8Array) => Promise<string>` | 按字节写文件到目标目录。**返回实际写入的绝对路径**（重名时宿主会自动加 `_1`），所以请以返回值而非预期值为准 |
| `pickDirectory` | `(title: string) => Promise<string \| null>` | 弹目录选择框。取消或非桌面环境返回 `null` |

### 3.7 `api.board`

| 方法 | 签名 | 说明 |
|---|---|---|
| `currentSpacePath` | `() => string \| null` | 当前空间文件夹绝对路径；未打开空间为 `null` |
| `createCardFromFile` | `(input) => Promise<boolean>` | 在画布上加一张「已存在于硬盘」的卡片 |

`CreateCardInput`：

| 字段 | 说明 |
|---|---|
| `relativePath` | 空间内相对路径，写入 `card.filePath` |
| `absolutePath` | 绝对路径，用于读图片尺寸 + 登记资源表 |
| `type` | 卡片类型（核心三类型之一，或插件注册的类型 id） |
| `x` / `y` | 可选画布坐标；省略时放在视口中心 |
| `w` / `h` | 可选尺寸；省略时按原图比例算 |
| `meta` | 插件私有数据，**由插件自己按 id 命名空间组织**（见 §5） |
| `note` | `type: 'note'` 时的便签正文预填（2026-09-20 新增；官方示例「日期便签」依赖） |
| `undoable` | 是否记入撤销历史，默认 `true`。**插件现画的二进制文件必须传 `false`**（见下） |

**三条必须知道的规则**：

1. **异步，且不能省步骤**。宿主需要读图片原始尺寸、登记资源表、再走 `addCards` 命令 ——
   少一步卡片就没有正确的宽高比、图片显示不出来。
2. **未打开空间 / 未挂桥时返回 `false`**，而不是抛错。请据此给用户一句中文说明
   （参照色卡插件：`skipNoBridge` / `skipNoSpace` / `skipOutsideSpace` / `skipRejected`
   四条文案，都点明「文件已经写好了」）。
3. **`undoable: false` 什么时候必须传**：插件自己生成的二进制（如现画的 PNG）没有
   「源文件」可供 redo 重新复制。若进了撤销栈，一次「撤销」会**删掉用户刚要的文件**，
   而 redo 再也造不回来。卡片本身仍可被正常移除（走卡片自己的移除命令）。

### 3.8 `api.config`

| 方法 | 签名 | 说明 |
|---|---|---|
| `getAll` | `() => Record<string, unknown>` | 读当前配置快照 |
| `set` | `(patch) => Promise<void>` | **浅合并**写入并立即落盘 |

- 配置存在 `%APPDATA%\Mindscape\plugins.json` 的该插件 `config` 字段里。
- **卸载不删配置**：卸载只删安装目录并把 `dir` 置空，`config` 原样保留
  （与「卡片 meta 不因卸载而蒸发」同一约定）。重新安装后配置还在。
- 配置是用户能手改的文件，**读的时候任何坏值都要回落默认、绝不抛错**
  （参照 `colorCard/options.ts` 的 `optionsFromConfig`）。

## 4. 数据扩展位（§4「接口 4」）

17.8 明确：**不需要额外接口**，直接用三处 `meta`：

| 位置 | 用途 |
|---|---|
| `card.meta` | 卡片级扩展数据 |
| `partition.meta` | 分区框级扩展数据 |
| `layout.extensions` | 布局级扩展数据 |

它们都是 `Record<string, unknown>`，**随数据一起经 zod 往返落盘**，不改 schema。

### 4.1 命名空间约定

```ts
meta: {
  'your.plugin.id': { /* 你自己的东西，键名与值随你定 */ },
}
```

宿主做的是**浅合并**（`{ ...card.meta, ...input.meta }`），它不认识各个插件，
不可能替你决定嵌套层级 —— 所以顶层键请用插件 id。

**例外：宿主已定义的通用字段**（用 `@/core/board/cardMeta.ts` 的常量，别硬写字面量）：

| 字段 | 类型 | 谁读它 | 效果 |
|---|---|---|---|
| `meta.tags` | `string[]` | 三种核心卡片类型统一渲染 | 卡片上显示标签胶囊（文件卡 / 便签在底部通栏，图片卡在顶部外挂层） |
| `meta.hoverLabel` | `string` | 图片卡渲染层 | **默认不显示**，鼠标悬停在卡片上时在**图片区域外的左下角**淡入（`group-hover`，与右下角的分辨率徽章左右对称）。色卡插件把色号写在这里 |

```ts
import { HOVER_LABEL_META_KEY, metaWithHoverLabel } from '@/core/board/cardMeta'
```

> `hoverLabel` 刻意做成**通用**字段而不是「核心认识色卡」：核心只回答
> 「这张卡有没有一个悬停标记」，标记是什么、谁写的，它不关心。任何插件都能用。

## 5. 持久化与状态存储

### 5.1 `plugins.json`

位置：`%APPDATA%\Mindscape\plugins.json`（与 `identifier` 无关，走 `dataDir()`）。

```json
{
  "version": 1,
  "plugins": [
    {
      "id": "example.hello",
      "enabled": true,
      "source": "external",
      "version": "1.0.0",
      "dir": "C:\\Users\\you\\AppData\\Roaming\\Mindscape\\plugins\\example.hello",
      "config": { "lastColor": "#5A7D6A" }
    }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `version` | 数据版本（当前 `PLUGINS_FILE_VERSION` = 1）。**迁移管道已实现**：schema 变更时在 `pluginStoreFile.ts` 的 `PLUGIN_FILE_MIGRATIONS` 登记升级步骤，老文件加载时自动迁移、下次落盘盖上新版本号；version 高于当前支持的版本会被拒绝加载（防旧应用覆盖新数据） |
| `id` | 与 `manifest.id` 一致 |
| `enabled` | 是否启用 |
| `source` | `builtin` / `external` |
| `version` | 最后一次**成功加载**时的版本号（用于「是否有更新」提示） |
| `dir` | 外部插件安装目录；卸载后为 `null`；内置恒为 `null` |
| `config` | 插件私有配置，**卸载不删** |

### 5.2 两条容错设计（照抄即可）

- **原子写**：`.tmp` + rename（`core/storage/atomicWrite.ts`），与 `spaces.json` 同一套策略。
  写一半断电不会留下损坏文件。
- **损坏容错**：解析失败 → 备份 `plugins.json.bak` → **以空列表启动，原文件不动** →
  把中文原因交给设置页展示。

## 6. 纪律：会让门禁变红的清单

`src/__guards__/architecture.test.ts` 里有六条硬规则，插件代码**同样受约束**。

| 规则 | 内容 | 对插件的影响 |
|---|---|---|
| **1** | 大文件行数只减不增（`Board.tsx` 2080、`Canvas.tsx` 1185） | 插件代码别往这两个文件里塞 |
| **2** | `window.confirm/alert/prompt` 只能出现在 `nativeDialogs.ts` | 插件要弹确认框就自己画界面，或走 `api.ui` |
| **3** | 不得硬编码配色 | class 里不许出现 Tailwind 内置调色板类名；hex 只允许出现在「本身就是数据」或「canvas 2D 绘制」处，且必须登记进豁免清单并写明原因 |
| **4** | `core` 只能依赖 core 与自己（白名单） | 插件代码**不要**放进 `core/` |
| **5** | 模块之间不得循环依赖 | 文案文件（`text.ts`）**不 import 任何模块**，是最省事的防环手段 |
| **6** | 新增源文件必须带同名测试 | 纯逻辑文件必须有 `.test.ts`；渲染层可进 `UNTESTED_ALLOWLIST` 但要写明原因 |

### 6.1 代码风格约定（项目级，非守卫强制）

- 每个模块顶部写**中文说明**，并注明对应的开发计划书章节（插件不涉及章节的写清意图）。
- **注释一律中文**（含行内注释）—— 中文是项目的工作语言。
- **用户可见文案一律进常量表**（如 `text.ts`），不要散落在 JSX 里。
- 纯函数与界面分离：界面只负责把值绑到控件上，**所有判断都在已测的纯函数里**。
- 不引入第三方库（10.1 依赖清单之外一律不批）。图标用内联 SVG，不装图标库。

### 6.2 可测性套路（本项目不引入 jsdom）

这是写插件时最需要提前想清楚的一件事 —— **React 组件在 node 环境下测不了**。三条应对：

1. **把逻辑抽成纯函数**：参数归一化、校验、文件名、尺寸换算、配置往返……
   全部放 `.ts`，组件里只剩绑定。
2. **把副作用做成可注入的依赖**。例：色卡的 `saveColorCard(request, deps)` 把
   `writeBytes` / `createCardFromFile` / `render` / `now` 全部作为参数传入 →
   node 环境能把成功、失败、跳过三种路径全测完，不需要 Tauri、不需要画布。
3. **把宿主能力做成可注入的假实现**。例：PNG 渲染的 `createCanvas` 可注入 →
   测试塞一块「记录绘制指令的假画布」，把「底色铺满 / 尺寸正确 / **不画任何文字**」
   钉死，而不必渲染真实像素。

## 7. 调试

### 7.1 用设置页看状态

**设置面板 → 插件** 提供：

| 操作 | 说明 |
|---|---|
| 列表 | 插件名、版本、来源（内置/外部）、状态、贡献摘要 |
| 启用 / 停用 | 主开关。停用会立即回收该插件的注册（菜单项当场消失） |
| 详情 | 清单信息、安装目录、贡献数量、插件私有配置、失败原因（中文） |
| 卸载 | 仅外部插件。停用 + 删安装目录 + **保留配置** |
| 重新加载 | 仅外部插件。重读 manifest 与入口文件（改完代码点它） |
| 刷新 | 重新扫描 `plugins` 目录（新拷进来的插件点它才出现） |

### 7.2 常见错误对照表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 状态 `invalid`，detail 说「插件 id 必须是小写反向域名风格」 | `id` 写成 `Hello` 或只有一段 | 改成 `com.example.hello` 这种形状 |
| 状态 `invalid`，detail 说「入口必须是插件目录下的 .js / .mjs 文件名」 | `main` 写了路径 | 只写文件名，比如 `index.js` |
| 状态 `error`，detail 说「未导出 activate(api) 函数」 | 入口没导出 `activate`，或写成了默认导出 | 用 `export function activate(api) {}` |
| 状态 `error`，detail 说「入口加载失败」 | 语法错误 / 顶层抛错 / 相对 import 找不到 | 检查文件与相对路径 |
| 启用成功但菜单里没有 | 内置插件没登记进 `builtinPlugins.ts`；外部插件没点「刷新」；或停用了 | 对照 §0.2 / §7.1 |
| 日志出现「重复注册，已用新定义覆盖旧定义」 | Vite HMR 重跑模块时又注册了一遍 | **正常现象**，不静默是有意的（否则开发期会直接崩） |
| 插件注册的卡片类型不生效 | `type` 与核心三类型（`image`/`file`/`note`）同名，被核心优先覆盖 | 换个类型 id |
| 插件菜单项不显示 | `id` 与核心菜单项同名（保留核心） | 换个 id |
| 注册了钩子收不到事件 | 宿主尚未埋点（见 §3.4） | 知情即可，别依赖 |

### 7.3 日志前缀

- `[pluginCenter] ……` —— 注册表：重复注册、钩子回调抛错。
- `[pluginHost] ……` —— 宿主：读取插件目录失败、保存状态失败、`deactivate` 抛错。
- `[cardTypes] ……` —— 卡片类型：插件注册的类型与核心同名，已忽略。

插件系统坏掉**绝不会让应用起不来**：`bootstrapPlugins` 吞掉异常只记日志；
`plugins.json` 损坏时备份并以空列表启动。

## 8. 完整示例：带界面 + 配置 + 建卡的插件

以仓库内的色卡插件为参照（`src/plugins/colorCard/`，六个模块各司其职）：

```
index.tsx    元信息 + activate：registerCanvasMenuItem → api.ui.openDialog
text.ts      全部中文文案（不 import 任何模块）
options.ts   参数模型与纯函数：预设 / normalizeHex / clampSize / sizeForRatio /
             文件名 / optionsFromConfig / optionsToConfig   ← 有 options.test.ts
png.ts       Canvas 2D → PNG 字节（createCanvas 可注入）      ← 有 png.test.ts
save.ts      生成 → 写盘 →（可选）建卡 的编排（依赖全注入）    ← 有 save.test.ts
dialog.tsx   用户界面（交给宿主挂载，登记在 UNTESTED_ALLOWLIST）
```

关键片段：

```tsx
// index.tsx —— 注册入口，把界面交给宿主挂载
activate(api) {
  api.registerCanvasMenuItem({
    id: COLOR_CARD_MENU_ITEM_ID,
    label: COLOR_CARD_TEXT.menuLabel,
    action: (ctx) => {
      api.ui.openDialog(COLOR_CARD_TEXT.dialogTitle, () => (
        <ColorCardDialog api={api} spacePath={ctx.spacePath} />
      ))
    },
  })
}
```

```ts
// save.ts —— 副作用编排，依赖全注入（这是能在 node 环境测完的原因）
export async function saveColorCard(
  request: SaveColorCardRequest,
  deps: SaveColorCardDeps,   // writeBytes / createCardFromFile / render / now
): Promise<SaveColorCardResult>

// 建卡时必须传 undoable: false —— 现画的 PNG 没有源文件可供 redo
await deps.createCardFromFile({
  relativePath, absolutePath, type: 'image',
  meta: metaWithHoverLabel({ 'mindscape.color-card': { color, width, height } }, color),
  undoable: false,
})
```

**这个插件体现的四个可复用经验**：

1. **文件是产物，卡片是视图**。产物是存到文件夹的 PNG；建卡只是顺手的便利。
   所以「输出目录不在空间内」不是错误，而是「只写文件」+ 一句中文说明。
2. **归一化之前校验**。色值必须先按用户输入校验再归一化，否则一个错字会被静默
   换成默认色 —— 用户以为自己选了想要的色，其实生成了另一张。
3. **零 Rust 改动**。Tauri 侧没有图像编码依赖（依赖清单锁定），用 WebView2 自带的
   Canvas 2D 画 + `toBlob('image/png')`，落盘复用已有的 `write_file_bytes`。
4. **刻意不注册独立卡片类型**。色卡就是一张 PNG，刷新空间后文件会被扫描器识别为
   图片卡；若注册独立类型，就会出现「只在本次会话里存在、重开空间变图片卡」的
   观感不一致。现在两种情形观感一致，`card.meta` 仍然保留。
